# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page, scroll-driven site about New York. Vanilla HTML/CSS/JS, **no build
step, no framework, no package.json**. The centrepiece is a pinned scroll journey
that dives from an aerial map into four places and yanks back up again.

Live at <https://yrxmania-77.github.io/nyc-scroll-site/>, deployed from `main`.

Deeper context lives in three files and should be read before non-trivial work:

- `NYC Folder/DESIGN.md` — the visual system, plus the **binding contracts**
  (shape, seam geometry, image quality/performance). Most of it is measured
  findings, not preference.
- `NYC Folder/PRODUCT.md` — product truth, real facts used as copy, accessibility
  requirements. Its audience section is explicitly labelled as assumed.
- `README.md` — the public-facing summary: layout, deployment, why generated
  media is committed.

## Layout

| Path | Role |
|---|---|
| `NYC Folder/` | All code: markup, styles, scripts, docs. |
| `main scroll folder/` | All media, source **and** derived. Never copy media out of it. |
| `NYC Folder/main scroll folder` | **Symlink** to `../main scroll folder`. Do not delete. |

Media is referenced without a leading `../` (e.g. `main%20scroll%20folder/...`),
which resolves through that symlink. That is what lets the site be served from
either directory locally. Spaces must be `%20`-encoded in URLs.

Derived media (all generated by `scripts/media-pipeline.sh`, all JPEG):

- `frames/<clip>/0001.jpg…0121.jpg` — desktop frame sequences, native size
- `frames-sm/<clip>/` — 1280×720 set for small screens / save-data
- `stills/<place>-{hold,return,mapstart}.jpg` — seam and hold images, always resident
- `optimized/` — hero and gallery stills

## Commands

There is no build, lint, or test suite. Verification is done by driving a real
browser; every script below assumes the server is already running.

```bash
# Serve. Use this rather than `python3 -m http.server`: that sends only
# Last-Modified, so browsers cache heuristically, and with no build step there
# are no hashed filenames to bust a stale copy. An edit then appears not to
# have worked when it did — this has already cost one wasted round trip.
python3 "NYC Folder/scripts/serve.py"
#   -> http://localhost:8080/NYC%20Folder/index.html

# From NYC Folder:
python3 scripts/qa.py [desktop|mobile|reduced]   # console errors, failed requests,
                                                 # screenshots to /tmp/nyc-qa/
python3 scripts/scroll-check.py [desktop|mobile] # smoothness, seams, pacing
python3 scripts/boundary-check.py                # parks the scrub either side of every
                                                 # segment join; catches pops a moving
                                                 # scroll cannot distinguish from motion
python3 scripts/shape-check.py                   # asserts the user-locked shape contract
python3 scripts/motion-table.py                  # regenerate MOTION_LUT (prints; paste it)
bash scripts/media-pipeline.sh                   # re-export ALL frames (~5-10 min)
```

Run `scroll-check.py` after any change to frame size, canvas sizing, or the draw
path. Run `boundary-check.py` after any change to the segment timeline, the scale
ramps, or `MOTION_LUT`. Run `shape-check.py` after any styling change.

**Do not open `index.html` as `file://`.** ES modules and fonts are CORS-blocked
there, so `journey.js` never runs and the journey renders as a black box.

## Deployment

`.github/workflows/pages.yml` publishes to GitHub Pages on every push to `main`.

It **assembles** the site rather than publishing the tree as-is, and that is
load-bearing: GitHub Pages does not follow symlinks, so `NYC Folder/main scroll
folder` would be served as a text file containing the path it points at and all
968 frames would 404. The workflow puts `index.html` and a *real* `main scroll
folder` side by side, then asserts 8 clips and 968 frames before deploying. The
`.mp4` sources are excluded — nothing on the site requests them.

A Stop hook (`.claude/hooks/auto-push.sh`) commits and pushes after each task so
the live site stays current. It refuses above 200 staged files, because a frame
re-export is 1,936 files and ~570MB.

## Architecture

### Three delivery modes

`js/journey.js` picks one at boot and rebuilds live if `prefers-reduced-motion`
changes. The section must never render as a blank dark box.

| mode | when | behaviour |
|---|---|---|
| `scrub` | GSAP present, motion allowed | pinned canvas frame sequence |
| `static` | reduced motion, or GSAP missing | stills stacked in normal flow, cards moved inline |

A `BLANK` canvas in `qa.py`'s reduced-motion run is **correct** — that mode
replaces the canvas with stills. Static mode also needs its own copy of anything
built for the pinned stage; see `.journey--static` in `site.css`.

### The journey is a weighted segment timeline

One pinned ScrollTrigger spans ~19 viewports. Scroll progress resolves to
`(segment, t)` and then to `(clip, frame)`. The mapping is **pure** — progress
in, state out, no playback state — which is what makes reverse scrolling work
for free.

Segments: `hub`, then `dive → hold → pullup` per place. Every clip is exactly
121 frames, so the weights in `W` *are* the rate: dives run at half the frames
per viewport that pull-ups do, identically at every place.

Within a clip, `t` does **not** map linearly to frames. `MOTION_LUT` inverts
each clip's measured cumulative-motion curve so equal scroll buys equal *screen*
motion — the source camera eases in and settles, and replaying that ease on top
of the visitor's own scrolling is what reads as "crawls, then blasts past".

**Consequence: scroll position and frame position are different numbers.**
Anything measured against a specific frame — the scale ramps, both seam windows
— must be keyed to the frame index, never to `t`. At the head of a pull-up,
`t = 0.03` is already ~20 frames in.

### Rendering

`Stage` draws cover-fit to a canvas sized `devicePixelRatio × CSS`, capped at 2.
`ScrubJourney.tick()` runs in a rAF loop reading the latest scrub value, never
from the ScrollTrigger callback, and skips the draw when nothing changed. Three
things layer on top, all documented with their measurements in DESIGN.md:

- a **scale ramp** per clip, because the source clips disagree on framing
- a **seam dissolve** in the pull-up's blurred tail, because they disagree on perspective
- **quantised sub-frame blending**, because a second full-canvas draw per tick is
  the single largest performance cost at retina

### Memory

One clip is ~894MB decoded, so nothing holds a whole journey. `ClipStore` keeps a
3-clip window (`KEEP_BACK`/`KEEP_AHEAD`) and `Clip.warmAround()` keeps only ~30
frames decoded around the playhead.

### Section transitions

**`hero → about` is a deliberate hard cut — 179.8 luma, no gradient.** It used
to be a mirrored pair; the user removed the hero half after three rounds of
tuning the haze out of it: "I'd rather have a clean hard edge than the foggy
glow." `shape-check.py` now fails if `.hero__melt` reappears. Do not soften it.

What remains is `about → journey`: the section colour dissolving back into the
map (`.journey__melt`). The rules below are what that seam is built on, and the
starting point for anyone the user asks to re-add a hero dissolve.

Two rules, both learned by measurement:

- **Curve is `1 - smoothstep`, flat at both ends.** A power curve is steepest
  exactly at the paper end, which is the end touching the next section — it
  reopened the seam to 15.8 luma.
- **Haze is distance, not brightness.** The 99th-percentile pixel never exceeds
  `--paper-deep` anywhere — the brightest row mean sits *below* paper, and with
  the gradient off the hero's bottom 300px is flat. What reads as milky fog is
  how far the gradient spends half-faded, so the fix is always a shorter band,
  never a darker one. Both seams take that length from one token, `--melt`
  (4svh), so they match in pixels rather than in percent of two different boxes.

`.journey__melt` scales its gradient's *reach* (`--arrive`), not a sheet's
opacity — fading a uniform cover made the stage's top edge translucent the moment
it appeared, which cut at 64 luma.

**Shortening `--melt` silently re-tunes the journey's tail** — the same class of
coupling as a frame-mapping change re-tuning the blend constants. The band can
only retract, never fade, so a *linear* retraction ends by compressing a
full-strength fade into a sub-pixel band: 61 luma at 4svh, against ~50 for a
visible edge. `site.js` square-roots `--arrive` to hold that tail open. Measure
the tail, not just mid-travel, after touching either.

### Gallery

A justified mosaic, not a fixed grid. Each band is a flex row; each cell grows in
proportion to its own aspect ratio (`--ar`, from the file's real dimensions) with
a zero basis, so width lands at `ar × k`, height at `k`, and the band consumes
its width exactly. Gaps are impossible by construction, and swapping an image
only changes its `--ar`. The previous fixed 6-column grid measured 80% filled.

Quote tiles are cells in the same system, with their own `--ar`. Descriptions
open as translucent overlays; closed panels are `inert`, not merely transparent.

### The About section is flat on purpose

It has no field, no overlay, no mask and no gradient — just `--paper-deep` and
the copy. Two treatments were removed from it in successive revisions (the hero
focus falloff, then an image field), both at the user's request.

**The second one is the trap.** The user reported a "foggy white blurred haze"
in the middle of the section and asked for every blur and overlay to be deleted.
There were none: the haze was the image itself, a soft-focus silver gradient
brighter than the page in places. An out-of-focus image cannot be de-fogged in
CSS. Before adding any field here again, open the file and check it is sharp.

### Contact form

Posts to Formspree. The markup is a real `<form action method="POST">`, so it
works with JS disabled (the browser just leaves the site for Formspree's
thank-you page); `contactForm()` in site.js upgrades that to `fetch` and reports
inline. Validation is the browser's — the `submit` event never fires while a
`required` field is empty, so there is no hand-rolled validator.

**The endpoint is a placeholder (`YOUR_FORM_ID`) until the user pastes a real
one.** site.js detects that string and refuses to submit rather than POSTing into
a 404 that would look exactly like success. A `mailto:` fallback sits under the
form because PRODUCT.md requires the contact CTA to reach a real address, and
both "Get in Touch" buttons now scroll to `#contact` instead of opening mail.

### CSS

`css/tokens.css` (vocabulary) → `css/site.css` (components) → `css/fonts.css`
(self-hosted faces). Never hardcode a colour in `site.css`; add a token. Use
`color-mix(in srgb, var(--token) N%, transparent)` for gradient stops so the end
colour matches its section by construction.

Fonts are self-hosted deliberately — Google Fonts timed out on 2 of 3 attempts
from this network and Archivo Black was silently falling back to Helvetica, which
the wordmark and closing statement both depend on. Do not reintroduce the CDN.

## Things that will mislead you

Each of these was gotten wrong once, at real cost:

- **Benchmark with the GPU.** Headless Chromium defaults to SwiftShader, a
  software rasteriser, where a retina canvas drops ~2/3 of frames. Measuring
  there once justified capping the canvas and shipped a visibly soft scrub.
  `scroll-check.py` already passes `--use-angle=metal --enable-gpu`; any new perf
  script must too.
- **`getImageData` on a retina canvas is a ~20MB GPU readback.** Sampling pixels
  inside a timed scroll reports dropped frames that do not exist.
- **Let the scrub settle before sampling** (~1.7s at `scrub: 0.6`). A shorter
  wait measures the harness's own lag and invents artefacts.
- **There is no 1080p source and no `<video>` element.** Clips are 2208×936 and
  1856×1112, cropped to a shared 16:9, so 1664–1856px wide is full quality.
  Extracting at 30fps only duplicates frames.
- **This ffmpeg has no `libwebp`.** Everything is JPEG. WebP would not help
  anyway — decoded size is `w × h × 4` regardless of codec. (There *is* an AVIF
  muxer via `libsvtav1`, but it decodes slower than JPEG for identical decoded
  size, so it would make the scrub worse, not better.)
- **Encoder quality cannot affect smoothness.** Same reason: `w × h × 4`. A
  `-q:v` change moves download time only. If a quality bump appears to cost
  frames, something else changed at the same time — isolate before concluding.
- **A frame-mapping change silently re-tunes the blend constants.** `MOTION_LUT`
  holds frame velocity constant, which parked the whole journey just inside a
  `BLEND_MAX_SPEED` of 1.2 and blended 51% of ticks — 1% → 4% dropped, with no
  other cause. Re-check `BLEND_MAX_SPEED` and `BLEND_STEPS` after touching pacing.
- **Never move media to Git LFS.** Pages does not resolve LFS pointers, so every
  frame would 404 and the journey would go black. The repo is ~770MB against
  GitHub's 1GB soft warning, and each frame re-export adds ~570MB to history
  permanently — if that becomes a problem, generate frames in the workflow rather
  than reaching for LFS.
- **Shape and chrome are user-locked.** Nav, buttons and chrome are rounded; the
  notch belongs to journey place cards *only*. See DESIGN.md; it outranks
  detector findings and aesthetic judgement.
- **Every hero effect has now been removed, one per revision, all by the user.**
  The focus falloff, then the About image field, then the melt. `shape-check.py`
  has been inverted to match: it fails if a blur appears anywhere in `.hero`, and
  fails if `.hero__melt` comes back. The hero is a sharp, unwashed photograph
  meeting flat paper at a hard edge, and every part of that is deliberate.
  The scroll hint is light because of it — dark ink there measures 1.4:1.
- **The hero blur is gone, and that direction is now the locked one.** A focus
  falloff (`.hero__defocus`) existed for two revisions and the user removed it:
  "it's not working the way I want." The detector no longer requires it — it now
  sweeps `.hero *` for any blur and fails if one reappears. Do not reinstate the
  depth of field; the About section's image field is what replaced it.
- **No outer `box-shadow`, including on the glass card.** The contact card is
  glassmorphism minus the drop shadow, because the contract bans outer shadows
  page-wide and the sweep enforces it. Depth comes from an inset top lip. A brief
  asking for "soft shadow" does not by itself override the contract.

## Known, unfixed

- **`.label` fails contrast site-wide.** `--ink-faint` measures 2.44:1 on flat
  paper against a 4.5:1 floor. Overridden locally where it sits on media; the
  global token is untouched because changing it restyles every label on the page.
- **The hero headline and subline measure 2.61:1 and 3.25:1** worst-pixel. Fixing
  means darkening `.hero__veil`, which changes a locked hero.
- **The map perspective mismatch is hidden, not solved.** It exists in the
  footage; only re-rendered clips would remove it.

## Working agreements

- Use the `impeccable` skill for frontend/design work, but the SHAPE CONTRACT
  overrides its detector when they conflict.
- Verify in-browser on desktop **and** mobile before reporting anything done.
- Media filenames are kebab-case. Copy in the cards, stats and quotes are real
  facts supplied by the user — do not rewrite them, and do not invent new ones.
- Measure before concluding. Most wrong turns in this repo came from a plausible
  theory that a five-minute measurement would have killed.
